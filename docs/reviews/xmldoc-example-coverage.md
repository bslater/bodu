# XML-doc `<example>` coverage assessment

This document is the audit trail for the XML-documentation **`<example><code>` uplift** across the
Bodu production libraries. Every public type (and the non-trivial public methods within it) in each
in-scope library is assessed and assigned one of four decisions:

| Decision | Meaning |
|---|---|
| **example added (type)** | A type-level `<example>` showing the headline workflow was added. |
| **example added (method)** | A method-level `<example>` was added to a non-trivial key member. |
| **covered by type** | Member usage is evident from the type-level example; no separate example. |
| **trivial** | Enum, exception, plain DTO/record, `<inheritdoc/>`, or override with no special contract. |

**Scope.** All production libraries; Test/Testing projects, the `Bodu.CodeStyle` solution, generated
files (`*.Designer.cs`, `*.Catalog.cs`, `<auto-generated>`), and embedded-resource/data assets are
excluded.

**Convention.** Examples use the repo-standard block shape:

```
/// <example>
/// <code language="csharp">
///<![CDATA[
/// ... code ...
///]]>
/// </code>
/// </example>
```

### TOC integration pattern (per new guide)
1. Add the `.md` under `docs/guides/<library>/`.
2. Add a `<div class="bodu-card">` entry to that library's `index.md`.
3. Add the entry under the library's section in `docs/guides/toc.yml`.
4. Surface major guides on the relevant `docs/guides/topics/*.md` landing page.
5. Cross-link the API with `xref:` (e.g. `[xref:Bodu.Financial.ExchangeRate]`; generics use a
   backtick-escaped arity, e.g. `Bodu.Numerics.Fraction\`1`).
