    Class AsyncLock

    Provides an asynchronous, non-reentrant mutual-exclusion primitive whose acquisition can be awaited without blocking a thread.

    Remarks

    AsyncLock is the asynchronous analogue of the C# lock statement. Because a held lock may need to span an await, the lock is acquired with LockAsync() and released by disposing the AsyncLock.Releaser it returns, typically with a using statement.

    The lock owns an explicit FIFO wait queue rather than delegating to SemaphoreSlim. When the lock is free, acquisition completes synchronously and allocates nothing; only a contended acquisition allocates the awaited task. Waiters are granted ownership in strict first-in, first-out order. Each waiter completion source uses RunContinuationsAsynchronously, so the releasing thread never runs a waiter's continuation inline while holding the internal gate.

    The lock is not reentrant: a caller that already holds the lock and attempts to acquire it again on the same logical flow will deadlock. Following the package-wide rule, a free lock is acquired even when the supplied token is already canceled; the token only cancels an acquisition that must queue.

    Dispose() faults every still-waiting acquisition with ObjectDisposedException and rejects subsequent LockAsync() calls. Disposing is intended for shutdown; dispose only when no further acquisitions are expected. Releasing a holder's AsyncLock.Releaser after disposal is a harmless no-op.

    Examples
    private readonly AsyncLock _mutex = new();

public async Task UpdateAsync()
{
    using (await _mutex.LockAsync())
    {
        // Exclusive section; safe to await here.
        await SomeOperationAsync();
    }
}
