Bodu.Formats.Outlook guides

Recipe-style walk-throughs for the Outlook format readers: Bodu.Formats.Outlook, the shared MAPI value model; Bodu.Formats.Outlook.Msg, the read-only reader for the Outlook message format (.msg / MS-OXMSG); and Bodu.Formats.Outlook.Pst, the read-only reader for the Outlook personal-folders format (.pst / MS-PST). A message is opened as a disposable session exposing every decoded MAPI property, the recipient and attachment tables, nested attached messages, named-property resolution, and the text, HTML, and compressed-RTF bodies. A mail store is opened as a disposable session exposing the store properties, the folder hierarchy, and every message in it with the same surface, embedded messages and store-wide named-property resolution included.

A .msg file is an OLE2 compound file: the message's properties live in a __properties_version1.0 stream of fixed 16-byte records, variable-length values live in __substg1.0_ streams named by their property tag, and recipients and attachments are indexed child storages. The container is read by CompoundFile, on which the reader is built. A .pst file is a node database: each folder, message, and attachment is a node whose properties live in a property context and whose children are listed in table contexts. The container is read by PstFile, on which the mail-store reader is built.

How the library works

OutlookMessage opens the container and eagerly decodes the root property stream, so the property surface is available without further I/O. Recipients, attachments, and the named-property mapping are materialized lazily on first access. Attachment payloads stream directly from the container, and an attached message opens recursively as a nested session sharing the root's container.

OutlookMailStore opens the container and parses only its header. Folder and message enumerations stream table rows, each store, folder, message, and attachment decodes its properties once on first access, attachment payloads stream from the container, and an embedded message opens as a view bound to the same session.

The three packages share the flattened Bodu.Formats.Outlook namespace: the value model - MapiPropertyTag, MapiProperty, the tag-addressed MapiPropertyCollection, and MapiNamedProperty - carries no container knowledge, so the .msg reader and the .pst mail-store reader (over Bodu.IO.Pst; see the Bodu.IO.Pst introduction) share it unchanged.

These guides cover the read path only - the readers never write .msg or .pst files, emulate a MAPI session, or de-encapsulate RTF into HTML.
