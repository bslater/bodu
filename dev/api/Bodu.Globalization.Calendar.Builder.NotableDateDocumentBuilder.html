Examples

NotableDateResource resource = NotableDateDocumentBuilder.Create("contoso-holidays")
    .AddAdjustmentPolicy("weekend-roll", p => p
        .When(AdjustmentTrigger.IfWeekend)
        .Then(AdjustmentAction.MoveToNextWorkingDay)
        .Emit(EmissionMode.ObservedOnly))
    .AddNotableDate("christmas", "Christmas Day", NotableDateCategory.PublicHoliday, c => c
        .AsNonWorkingByDefault()
        .AddRule("fixed", r => r
            .Fixed(12, 25)
            .WithAdjustment("weekend-roll")))
    .Build();

NotableDateService service = new(resource);

// The same model serializes to XML or JSON for storage or distribution.
NotableDateDocumentBuilder builder = NotableDateDocumentBuilder.Create("contoso-holidays")
    .AddNotableDate("new-year", "New Year's Day", NotableDateCategory.PublicHoliday, c => c
        .AddRule("fixed", r => r.Fixed(1, 1)));
string xml = builder.ToXml();
string json = builder.ToJson();

Remarks

The builder accumulates an in-memory model of the document. Calling ToXml() or Build() renders the model to XML in the urn:bodu:globalization:calendar namespace; building then loads that XML through NotableDateResourceLoader, which remains the single source of validation and assembly. The XML form expresses every feature of the schema, whereas the JSON form rendered by ToJson() is restricted to a subset of the JSON form the loader reads.

Workflow. Obtain a builder with Create() or Create(string, string), declare reusable adjustment policies with AddAdjustmentPolicy(string, Action<AdjustmentPolicyBuilder>), add each notable-date concept with AddNotableDate(string, string, NotableDateCategory, Action<NotableDateDefinitionBuilder>), then terminate by materializing a NotableDateResource with Build(), serializing with ToXml() / ToJson() / Save(string), or wrapping the result with ToProvider().

Remarks

Enumeration values and the working week are read with the loader's rules, so they never parse into data the loader would read differently: an enumeration value must name a member (ignoring case; a number is not a name), and workingDays must be the seven-character, Sunday-first binary pattern. Any other value throws a FormatException carrying the message of the loader's BODU-CAL-ENUM or BODU-CAL-WORKING-DAYS diagnostic.

Integers, Booleans and an adjustment trigger's month are read with the loader's rules too: a present value must be a 32-bit integer, an XML-schema Boolean literal (true, false, 1 or 0), or a month name or number, and any other value throws a FormatException carrying the message of the loader's BODU-CAL-VALUE diagnostic.

The attribute values of a strategy, a recurrence and an end strategy are read the same way, each as the loader reads it: an integer, a Boolean, a weekday, week ordinal, direction or invalid-day behavior, a yyyy-MM-dd date, and a month, a fixed strategy's in the calendar the rule's applicability names. A value the loader rejects throws a FormatException carrying the message of its BODU-CAL-VALUE, BODU-CAL-ENUM or BODU-CAL-MONTH diagnostic, and a value it reads is written in the form the schema accepts: a name in another case as the member's name, a number in quotes by its digits, and a month as its English name, or a fixed month in a calendar other than the Gregorian as its number or its month alias.

Text is read as the loader reads it: a string verbatim, a number by its invariant digits, and a Boolean as true or false, so "displayName": 5 reads as the text 5. An item of a list of identifiers, territory codes or tags must be a string, and any other item throws a FormatException carrying the message of the loader's BODU-CAL-VALUE diagnostic; an item of a list of enumeration names is read by its JSON text, so a number there throws as a value that names no member, while an object or an array in a list of names or integers throws as a value of the wrong kind. The metadata, an adjustment policy's description and a rule's comment, which the loader does not read, accept the same scalars. Any other property that holds a value, holding an object or an array, a property that holds an object or a list, such as applicability or tags, holding a value of another kind, and an item of a list of concepts, rules, adjustment policies, imports, uses or overrides that is not an object, throw a FormatException carrying the message of the loader's BODU-CAL-VALUE diagnostic, while the JSON literal null reads as absent, as the loader reads it. The message names a value or an item of the wrong kind by its JSON kind (object, array, number, Boolean or null), as the loader's does, rather than quoting it.

Every field the loader's LoadJson reads is read, including those outside the JSON subset that ToJson() writes (imports, the trigger and action refinements, handler parameters, scope rule references and year bounds, and a PatchRule override's applicability, strategy, recurrence, duration, tags and adjustments), so the builder and the loader read the same document into the same resource. Property names are matched ignoring case, as the loader matches them, so "Strategy" reads as "strategy", and each strategy and recurrence attribute is written under its schema name, while a property the loader does not read is ignored, as the loader ignores it. The few fields the builder's model cannot hold throw a NotSupportedException rather than being dropped. A rule's strategy and recurrence, and a PatchRule override's when it carries either, must name exactly one recognized kind between them, matched ignoring case as the loader matches it, and an untilDate must declare an end strategy that names exactly one, or the document throws a FormatException carrying the message of the loader's BODU-CAL-RULE-SOURCE, BODU-CAL-DURATION-NOEND or BODU-CAL-DURATION-CONFLICT diagnostic, rather than building the first kind alone or none. An override's operation is matched ignoring case, as the loader matches it; one that is absent or names no operation throws a FormatException carrying the message of the loader's BODU-CAL-ENUM diagnostic, rather than being read as a PatchRule, and an AddRule override without a rule throws one carrying the message of its BODU-CAL-SCHEMA diagnostic, rather than adding a rule with an empty identifier.

The values the XML schema requires and the ranges it holds integers to are held to as the loader holds a JSON document to them: an object that lacks a property the schema requires of it (the root's schemaVersion and resourceId, a concept's id, displayName and category, a strategy's month, …), a concept's rules or a weekly recurrence's days that holds no item, and an integer outside the schema's range (a day count or interval below 1, a year outside 0 to 65535, a day of the month outside 1 to 31, an ISO week outside 1 to 53, or an ordinal that is zero, outside -366 to 366, or written with a plus sign or a leading zero) throw a FormatException carrying the message of the loader's BODU-CAL-SCHEMA diagnostic, rather than being read with a default in the value's place or written for the schema to reject at Build(). An empty list that is optional reads as absent. Each identifier, reference and territory code is held to the pattern the schema requires of it, as the loader holds it: the resource identifier, the concept, rule and adjustment policy identifiers, the references of an action, a strategy, an override, an import use and a scope, the adjustment policy references of a rule, a patch and an import use, an import use's alias, and the territory codes of a scope, an applicability and an import use. A value that breaks its pattern, such as New-Year for a concept identifier, throws a FormatException carrying the message of the loader's BODU-CAL-SCHEMA diagnostic.

Parsing does not otherwise validate the document: a document the loader would reject for a reason other than a malformed value, such as a dangling reference, can still parse. Validate with Validate() or TryBuild(out NotableDateResource?, out IReadOnlyList<NotableDateValidationDiagnostic>), or load the text with NotableDateResourceLoader, when the input is not trusted.

Exceptions

ArgumentException

json is null, empty, or white-space.

FormatException

json is not well-formed or is not a notable-date document, an enumeration, integer, Boolean, date, month, trigger-month or workingDays value does not parse, a property that holds a value holds an object or an array, a property that holds an object or a list holds a value of another kind, an item of a list of identifiers, territory codes or tags is not a string, an item of a list of concepts, rules, adjustment policies, imports, uses or overrides is not an object, a rule's strategy and recurrence, or a PatchRule override's when it carries either, name no recognized kind or more than one between them, an untilDate declares no end strategy or one that names no recognized kind or more than one, an override's operation is absent or names no operation, an object lacks a property the XML schema requires of it, a concept's rules or a weekly recurrence's days holds no item, an integer lies outside the range the XML schema allows, or an identifier, reference or territory code does not match the pattern the XML schema requires of it.

NotSupportedException

json declares a field the builder's document model cannot hold: an empty tags or adjustments list on a PatchRule override, an empty adjustments list on an import use, a scope rule reference that is a bare rule identifier, a handler parameter whose value is an object or an array, or a metadata name, description or source, an adjustment policy's description or a rule's comment that is an object or an array.

Save(string)

Serializes the document to a file, inferring the format from the file extension.

public void Save(string path)

Parameters

path string

The destination file path. A .xml extension writes XML, a .json extension writes JSON, and a .bcal extension writes a binary rule pack.

Examples

NotableDateDocumentBuilder builder = NotableDateDocumentBuilder.Create("contoso-holidays")
    .AddNotableDate("new-year", "New Year's Day", NotableDateCategory.PublicHoliday, c => c
        .AddRule("fixed", r => r.Fixed(1, 1)));

// The extension selects the format: .xml writes XML, .json writes JSON.
builder.Save("contoso-holidays.xml");
builder.Save("contoso-holidays.json");

// Reload the document later and build a service over it.
NotableDateResource resource = NotableDateDocumentBuilder.Load("contoso-holidays.xml").Build();

Remarks

XML and JSON are written as UTF-8 without a byte order mark, and the XML declaration names that encoding.
