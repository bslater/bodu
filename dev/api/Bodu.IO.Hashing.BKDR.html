Remarks

For each input byte c the hash is updated as hash = (hash * seed) + c. The Seed multiplier must be one of the supported values (31, 131, 1313, 13131, 131313, 1313131, 13131313, 131313131, 1313131313) and can be reassigned only while the algorithm has not yet consumed any input.

When to choose BKDR. BKDR is the polynomial rolling hash from K&R's "The C Programming Language" — a textbook choice for symbol tables, lexer keyword maps, and other small-string keying tasks. Pick it when interoperating with code that already uses the K&R formulation, or when the input is a short identifier and avalanche quality matters less than predictable behavior. For modern hash-table workloads prefer Fnv1a32 (better avalanche on the same per-byte cost) or MurmurHash3_32 (much better distribution on inputs longer than ~16 bytes).

Output and lifecycle. Produces a 32-bit (4-byte) digest in little-endian byte order. GetCurrentHash() is non-destructive; Reset() returns the instance to its reconfigurable, pre-input state. Instances are not thread-safe.

important

This algorithm is not cryptographically secure and should not be used for password hashing, digital signatures, or integrity validation in security-sensitive applications.

using Bodu.IO.Hashing;
using Bodu.IO.Hashing.Extensions;

// Default seed (131); appropriate for short identifier keys.
var bkdr = new BKDR();
byte[] digest = bkdr.ComputeHash(System.Text.Encoding.UTF8.GetBytes("Identifier"));
