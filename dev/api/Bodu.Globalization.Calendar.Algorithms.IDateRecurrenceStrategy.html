    Interface IDateRecurrenceStrategy

    Calculates every occurrence of a recurring notable-date pattern that falls within a bounded date range, such as every second Tuesday or the last Friday of every month.

    Namespace: Bodu.Globalization.Calendar.Algorithms
    Assembly: Bodu.Globalization.Calendar.dll
    Syntax
    public interface IDateRecurrenceStrategy
    Remarks

    A recurrence strategy is the multi-occurrence counterpart to IDateCalculationStrategy: where a single-date strategy yields at most one occurrence per year, a recurrence strategy can yield zero, one, or many occurrences within the requested window. A NotableDateRule declares exactly one occurrence source — either a single-date strategy or a recurrence strategy.

    Implementations must be deterministic and independent of CurrentCulture. The returned dates must be in ascending chronological order, contain no duplicates, and fall entirely within the supplied range. Generation is always bounded by the range; an implementation must never expose or produce an unbounded sequence, and whether a given date is an occurrence must not depend on the size or start of the query range (anchor-based patterns are query-window invariant).
