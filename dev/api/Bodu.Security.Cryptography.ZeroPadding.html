Examples

using Bodu.Security.Cryptography;

// Caller is responsible for tracking the original plaintext length -
// Unpad here returns the padded buffer unchanged.
IPaddingStrategy padding = new ZeroPadding();
byte[] padded = padding.Pad(plaintext, blockSize: 128); // 128 bits = 16 bytes

Remarks

Zero padding is not self-describing and cannot be unambiguously removed when the plaintext itself may end in zero bytes. Use this strategy only when the original plaintext length is recorded out-of-band or the data is known never to contain trailing zeros.

When to choose zero padding. Pick zero padding only when the surrounding format already records the plaintext length explicitly (e.g. a length-prefixed protocol frame or fixed-size record), or when the plaintext is text that cannot legitimately contain trailing 0x00 bytes. For ordinary length-recoverable padding pick Pkcs7Padding; for AEAD modes that handle alignment internally pick NoPadding.

StripsPaddingOnUnpad

Gets a value indicating whether Unpad(ReadOnlySpan<byte>, int) inspects the final block and may return fewer bytes than it received. Self-describing schemes such as PKCS#7, ANSI X.923, ISO 10126 and ISO/IEC 7816-4 return true; pass-through schemes such as zero padding and no padding return false.

Remarks

Streaming block-cipher transforms use this flag to decide whether the final ciphertext block must be deferred during decryption so that padding validation and removal can happen at the stream boundary.
