An IRateCache that persists a single provider's rates and fetch-coverage windows in an injected IDistributedCache - for example a Redis cache - expiring them through the same freshness mechanism as the in-memory, TOML, and SQLite caches.

Examples

// A distributed caching provider backed by a Redis IDistributedCache resolved from DI.
var options = new DistributedRateCacheOptions { Provider = "RBA" };
var cache = new DistributedRateCache(redisDistributedCache, options);
IDatedRateProvider cached = new CachingRateProvider(rba, cache, new CachingRateOptions());

Remarks

The full per-pair state is stored as a single JSON blob under one stable, collision-free key, {prefix}{provider}:{from}{to}. The blob carries both the cached rate rows and the recorded coverage windows. Decimal rates are serialized as invariant strings and all dates and instants as invariant ISO text (a DateOnly as yyyy-MM-dd, a DateTimeOffset in round-trip "O" form) so the full precision and scale round-trips losslessly, mirroring the TOML and SQLite caches' string-decimal choice.

Because a pair's whole state travels as one blob, this backend fits the whole-state seam of RateCacheBase<TOptions> exactly: the read-merge-write mechanism, per-pair locking, snapshot read, and the shared RateCacheRules policy are all inherited, and this class contributes only the blob serialization. A single StoreFetchedRange(CurrencyPair, IReadOnlyList<CachedRate>, DateOnly, DateOnly, TimeSpan, DateTimeOffset) set is all-or-nothing - the reader never observes coverage without its rows even across processes - while cross-process concurrent writes to the same pair remain last-write-wins, consistent with the documented best-effort nature of the contract.

As required by IRateCache, a backing-store failure surfaces as an empty read or a skipped write rather than an exception: IDistributedCache faults and JSON (de)serialization faults degrade gracefully, while argument validation still throws.
