Represents a dictionary whose indexer getter materializes missing entries on demand: reading an absent key invokes a value factory, stores the produced value, and returns it.

Remarks

DefaultingDictionary<TKey, TValue> is the .NET analogue of Python's collections.defaultdict: the ValueFactory delegate fixed at construction plays the role of default_factory, and - exactly as in Python, where __missing__ fires only for d[key] - only the indexer getter materializes defaults. TryGetValue(TKey, out TValue), ContainsKey(TKey), Remove(TKey), Count, and enumeration observe only entries that have actually been stored; none of them invoke the factory.

This differs from the GetOrAdd extension methods on IDictionary<TKey, TValue> in Bodu.Core, which stay the lightweight per-call-site option: there the factory is supplied at each call, whereas here the default-producing policy is baked into the dictionary itself so every plain indexer read applies it.

Reentrancy contract: when the factory itself mutates the dictionary - including adding an entry for the very key being materialized - the stored result is always the factory's return value. Any value the factory assigned to that key during its own execution is overwritten before the indexer returns. This keeps the contract deterministic: dictionary[key] on a miss always stores and returns what the factory returned.

TValue is unconstrained, so a factory returning null for a reference or nullable value type stores null as-is; the key is then present with a null value and the factory is not invoked for it again.

DefaultingDictionary<TKey, TValue> is not thread-safe. The indexer's check-invoke-store sequence is not atomic; concurrent access requires external synchronization. 

var groups = new DefaultingDictionary<string, List<int>>(_ => new List<int>());

groups["odd"].Add(1);     // miss - the factory creates the list, it is stored, then mutated
groups["odd"].Add(3);     // hit - the stored list is returned; the factory is not invoked

bool has = groups.ContainsKey("even");   // false - lookups never materialize defaults
int count = groups["odd"].Count;         // 2

Remarks

The getter never throws KeyNotFoundException: when the key is absent it invokes ValueFactory, stores the produced value, and returns it. When the key is present the stored value is returned and the factory is not invoked. Only this getter materializes defaults - every other read surface observes stored entries only.

If the factory mutates the dictionary - including assigning the very key being materialized - the factory's return value is stored last and wins; see the reentrancy contract in the type-level remarks.
