Remarks

The default algorithm computes hash = (hash * 33) + c for each input byte c. Setting UseModifiedAlgorithm selects the XOR-modified form, hash = (hash * 33) ^ c, which may give better distribution in some hash-table workloads.

Both InitialValue and UseModifiedAlgorithm are reconfigurable only while the algorithm has not yet consumed input. Reset() returns the instance to the reconfigurable state.

When to choose Bernstein. djb2 is the canonical "C-style" hash for short string keys — language symbol tables, environment-variable maps, and small associative containers. Pick it when interoperating with code that has standardized on djb2 (Perl, Python's older string hash, Tcl variable tables, etc.) or when the seed/variant flexibility is useful. Empirically the XOR-modified form (djb2a, UseModifiedAlgorithm set to true) gives slightly better avalanche than the default additive form. For new code without an interop constraint, Fnv1a32 is a closely related but better-distributing default; MurmurHash3_32 is preferable for inputs longer than a few dozen bytes.

Output and lifecycle. Produces a 32-bit (4-byte) digest in little-endian byte order. GetCurrentHash() is non-destructive; instances are not thread-safe.

important

This algorithm is not cryptographically secure and should not be used for password hashing, digital signatures, or integrity validation in security-sensitive applications.

using Bodu.IO.Hashing;
using Bodu.IO.Hashing.Extensions;

// Default djb2 with the canonical 5381 seed.
var djb2 = new Bernstein();
byte[] digest = djb2.ComputeHash(System.Text.Encoding.UTF8.GetBytes("symbol"));

// XOR-modified djb2a, generally better distribution.
var djb2a = new Bernstein { UseModifiedAlgorithm = true };
byte[] digestA = djb2a.ComputeHash(System.Text.Encoding.UTF8.GetBytes("symbol"));
