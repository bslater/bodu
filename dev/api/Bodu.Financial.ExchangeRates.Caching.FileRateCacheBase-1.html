    Class FileRateCacheBase<TOptions>

    Provides the file-storage mechanism for an IRateCache: layout-driven directory and file-name resolution, optional date partitioning, and best-effort file read and write. Derived types supply only the serialization format.

    Remarks

    A cache instance is bound to one provider, and the Layout decides where each pair's rows are stored: a single file per pair (the default), or — when the layout is partitioned — one file per calendar period under a per-pair folder. Reads and writes are best-effort: any IOException or UnauthorizedAccessException surfaces as an empty read result or a skipped write, so a storage problem never breaks rate retrieval. Derived types are expected to treat malformed content the same way by returning an empty list from Deserialize(string, string).

    For a partitioned layout a pair's rows are split across files by their observation date, and a recorded coverage window is split at partition boundaries so each file carries only the coverage for its own period; a read concatenates every partition file in the pair's folder and the shared cache rules re-merge the halves, so the split is lossless.
