    Class MovingSum<T>

    Maintains the sum and mean of the most recent N samples of a stream, updating in amortized O(1) as each new sample displaces the oldest.

    Remarks

    This is the finance / telemetry "rolling window" idiom: the window holds the last Capacity samples, Sum and Mean always describe exactly those samples, and until the window fills (IsFull) they describe the samples received so far. Samples are accepted as T and the sum is maintained in T — exact for integer, decimal, and BigInteger samples — while Mean is a derived result computed and returned as a finite double. The rolling-sum arithmetic is checked: a fixed-width integer sum that would overflow throws OverflowException from Add(T) rather than silently wrapping, and the window state is left unchanged when that happens. Floating-point sums cannot overflow (they saturate per IEEE 754); a sum that has saturated to infinity surfaces as OverflowException when Mean is read.

    For floating-point samples the subtract-on-evict update accumulates rounding drift, so the sum is transparently recomputed from the buffered window after every full window turnover, bounding the drift to one window's worth of rounding. Samples must be finite: NaN and infinite values are rejected by Add(T). For min/max over the same window, pair this type with MovingMinMax<T>; for whole-stream moments use RunningStatistics<T>.

    Examples
    var window = new MovingSum<double>(3);
window.Add(1.0);   // window: {1}          Sum = 1
window.Add(2.0);   // window: {1, 2}       Sum = 3
window.Add(3.0);   // window: {1, 2, 3}    Sum = 6
window.Add(4.0);   // window: {2, 3, 4}    Sum = 9, Mean = 3
