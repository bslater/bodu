Fields

Lenient = 0

Trailing non-whitespace after the closing ] is accepted silently. This matches the historical Bodu profile and is the default for documents authored against lenient dialects.

Strict = 1

Trailing content (whether word or comment-introducer) after the closing ] emits TrailingContentAfterSectionHeader. Trailing whitespace is always permitted.

AllowTrailingInlineComment = 2

Trailing inline comments (introduced by # or ;) after the closing ] are accepted and discarded; any other trailing content emits TrailingContentAfterSectionHeader.

Remarks

The parser identifies a section name as everything between the first [ on the line and the last ] on the line, allowing ] inside section names so EditorConfig pattern conventions remain usable. The handling of any text that appears *after* the final ] is a separate decision that this mode controls.

Under Lenient the parser accepts trailing content silently - useful when the document is authored against a lenient EditorConfig dialect that ignores trailing words. Under Strict the parser emits TrailingContentAfterSectionHeader so authors learn about typos. AllowTrailingInlineComment sits between the two: trailing comments (introduced by # or ;) are accepted, anything else still produces the diagnostic.
