Examples

BigDecimal price = BigDecimal.Parse("19.99");
BigDecimal tax = price * BigDecimal.Parse("0.10");   // 1.999
BigDecimal total = price + tax;                      // 21.989

BigDecimal third = BigDecimal.One / 3;               // 0.3333… (50 places, half-even)
BigDecimal half = BigDecimal.One / 2;                // 0.5 (exact)

Remarks

A BigDecimal is the value UnscaledValue × 10-Scale. Unlike decimal it has no fixed precision or range limit: both the number of significant digits and the exponent grow as needed.

Every value is held in a single canonical form so equal values share one representation and compare and hash equally: trailing zeros are removed from the unscaled value down to — but never past — a scale of zero, so 1.0 and 1.00 are the same value, and an integer such as 100 keeps a scale of zero.

Addition, subtraction, multiplication, and remainder are exact. Division is generally not exact (for example 1 / 3), so the / operator and Divide(BigDecimal, BigDecimal) round to a default working scale of DefaultDivisionScale decimal places using ToEven; use Divide(BigDecimal, BigDecimal, int, MidpointRounding) to choose the scale and rounding explicitly. Exact quotients self-trim through canonicalization, so 1 / 2 is 0.5.

public int CompareTo(BigDecimal other)

Parameters

other BigDecimal

The value to compare with.

Returns

int

A negative number when this value is less than other, zero when they are equal, and a positive number when this value is greater.

Remarks

The comparison decides on sign, then on equal scales, then on the operands' integer-magnitude bounds, and only rescales to a common scale when the magnitudes genuinely overlap. Rescaling multiplies an unscaled value by 10 raised to the scale gap, so short-circuiting first bounds the transient allocation that a pathological scale difference would otherwise force on every comparison.
