Examples

using Bodu.Numerics;

// Type inferred from the int literals.
var ints = Interval.ClosedOpen(0, 100);           // Interval<int>

// Type inferred from the decimal-suffixed literals.
var prices = Interval.OpenClosed(1000m, 10_000m); // Interval<decimal>

// Type inferred from the local variable.
double low = 1.5, high = 2.5;
var span = Interval.Closed(low, high);            // Interval<double>

Remarks

The methods on this class mirror the static factories declared on Interval<T> but accept the endpoint values directly, letting the compiler infer the endpoint type from the arguments. This avoids the need to repeat the generic parameter at the call site: Interval.Closed(1, 5) compiles to a Interval<T> over int without an explicit type argument, and Interval.ClosedOpen(0m, 100m) picks decimal from the literal suffixes.

Prefer the non-generic helpers when the endpoint type is obvious from the arguments - typical for literals, local variables, and expressions that already carry the type - and use Interval<T>'s own static factories (e.g. Closed(T, T)) when the call site needs an explicit type to disambiguate, when the endpoint type comes from a generic context, or when the factory is being held as a method group.
