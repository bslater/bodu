Remarks

The backing store is supplied by the dependency-injection container as an IDistributedCache (for example a Redis cache) rather than by these options; this type therefore carries only the bound provider and an optional KeyPrefix used to namespace the cache's entries so several applications, or several caches, can safely share one distributed store.

Freshness is supplied per call by the caching provider, so this type carries no caching duration of its own. Server-side lifetime is a separate concern: each written blob is stamped with an absolute expiration of the caching duration plus EntryExpirationMargin, so a key whose pair stops being queried self-evicts from the backing store instead of lingering forever. Set the margin to null to write entries without any server-side expiration (the pre-margin behaviour).

EntryExpirationMargin

Gets or sets the margin added to the caching duration when deriving each written blob's server-side absolute expiration, or null to write entries without any server-side expiration.

public TimeSpan? EntryExpirationMargin { get; set; }

Property Value

TimeSpan?

The expiration margin; defaults to one hour.

Remarks

Every entry this cache serves must already be fresh under the per-call caching duration, so an entry evicted server-side at duration + margin would in any case have been filtered on read - served results are unchanged in any normal configuration. The margin keeps the server-side lifetime comfortably behind the application-side freshness (including the shared one-minute clock-skew tolerance), so eviction never races a legitimate read.

One corner is worth knowing: a deployment that stores under one duration and later reads under a longer one (for example after raising the provider's expiry at runtime) could observe a server-side eviction where it previously saw a hit. Set the margin to null to opt out entirely and restore unbounded server-side lifetime.

KeyPrefix

Gets or sets the prefix prepended to every cache key the cache writes.

public string? KeyPrefix { get; set; }

Property Value

string

The key prefix, or null to write keys without a prefix.

Remarks

A prefix namespaces the cache's entries within a shared distributed store so that several applications, or several caches over different providers, do not collide. When set it is included verbatim at the front of every key; when unset, keys begin with the provider name.

Validation rejects only a value that is non-null but consists solely of white space. It does not constrain length or screen for control characters, so a prefix that a particular IDistributedCache backend rejects as a key is not caught here and surfaces only when the backing store is exercised.
