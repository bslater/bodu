# Definition of done for a shipping package (Phase 5.5 of reviews/docfx-coverage-audit-and-plan.md).
#
# One row per packable package, tab- or space-separated:
#
#   <package id>   <docs landing>   <guides>   <samples page>
#
# The three targets are resolved under docs/ as:
#   docs/docs/<docs landing>/index.md   (or docs/docs/<docs landing>.md)
#   docs/guides/<guides>/               (or docs/guides/<guides>.md)
#   docs/samples/<samples page>.md
#
# Several packages share a family page on purpose — the regional calendar data packs all land on
# calendar-data, the exchange-rate providers on exchange-rates — so the same target may appear on
# many rows. A '-' records a deliberate absence, reviewed rather than overlooked:
#
#   Bodu.IO.Biff                 no guide folder; the codec is documented through its landing page and
#                                the Excel guides that consume it.
#   Bodu.Text.Serialization      no samples page; the shared engine has no runnable sample of its own,
#                                it is exercised by every serializer sample.
#   Bodu.Formats.Outlook*        no samples page; there are no Outlook sample projects under samples/ yet.
#
# bld/check-docs.py 'packages' fails when a packable package has no row here, when a row names a
# target that does not exist, or when a row exists for a package that is no longer packable. Adding a
# package therefore forces a decision about its documentation rather than letting it ship unlisted.
