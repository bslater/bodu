# NuGet shipping manifest. `dotnet pack bodu.slnx` builds every packable project; only the
# packages listed here are pushed to nuget.org by .github/workflows/release.yml.
#
# Each line is "<PackageId> <first-shipped-version>": the id, then the lock-step version at which
# that package FIRST appeared on nuget.org. The version is not the version being released — that is
# BoduBaseVersion in bld/Versioning.props — it is a permanent record, written once when the package
# joins a wave and never edited again.
#
# It exists because the package-validation baseline (BoduPackageValidationBaseline) compares a pack
# against that package's own published predecessor. A package joining this release has no such
# predecessor, and pointing ApiCompat at one fails the pack with NU1102 before it compares anything,
# so Directory.Build.targets applies the baseline only when the baseline version is at or after the
# package's first-shipped version.
#
# Extending a release wave = append its package ids with the version they will first ship at, and
# bump BoduBaseVersion in bld/Versioning.props. See bld/RELEASING.md.

# --------------------------------------------------------------------------------------------
# Deliberately NOT published. These projects pack (the release workflow packs the whole solution)
# and are available as build artifacts, but are withheld from nuget.org on purpose. Listing them
# here, rather than leaving them absent, keeps a later wave from adding one without seeing why it
# was held back. Removing an entry from this list is the decision to ship it.
#
#   Bodu.Financial.ExchangeRates.Xe
#       Experimental. Authenticates with a token scraped from XE.com's bootstrap page, which has no
#       official endpoint, so the provider can stop working at any time through no fault of the code
#       and no release of ours can fix it. Publishing it means fielding issues that cannot be closed.
#
#   Bodu.Financial.ExchangeRates.Oanda
#       Same class of fragility. OANDA's Historical Currency Converter endpoint is undocumented and
#       gated by bot mitigation: the provider loads the site root to capture a challenge cookie and
#       re-primes when challenged. Working around anti-bot measures is a clear signal the operator
#       does not intend programmatic use, and the endpoint can change without notice.
#
#   Bodu.Globalization.Calendar.Tool
#       A PackAsTool CLI (`bodu-calendar`), not a library. Different consumer contract from every
#       other package here; warrants its own decision rather than a slot in a library wave.
#
#   Bodu.Globalization.Calendar.Build
#       An MSBuild integration package (DevelopmentDependency, IncludeBuildOutput=false). Same
#       reasoning as the tool it drives.
# --------------------------------------------------------------------------------------------
